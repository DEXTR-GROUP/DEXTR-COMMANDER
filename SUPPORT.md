# Support

Use the repository issue tracker for reproducible defects, documentation problems, and feature requests.

Before opening an issue:
1. read `README.md`;
2. read `SECURITY.md` for security-sensitive reports;
3. check existing issues;
4. provide the DEXTR Commander version or commit;
5. provide the transport used (stdio or Streamable HTTP);
6. provide the relevant Rust/toolchain and operating-system information;
7. include a minimal reproduction where possible.

Do not publish credentials, private keys, authorization codes, tokens, or host-specific secrets in issues.

Security vulnerabilities should follow the private disclosure procedure described in `SECURITY.md`, not a public issue.
